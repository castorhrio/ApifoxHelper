# Apifox 助手

按《Apifox 辅助工具：产品设计书 v1.1》实现的独立本地工具：从 C# 源码检查并补全接口注释，核对接口契约，再预览并同步到已有的 Apifox 项目和分支。

本目录自成一体：有自己的项目文件、`Directory.Build.props`/`Directory.Packages.props`（截断外层仓库的 MSBuild 继承），不引用任何业务项目，也不在业务解决方案中。可以整个目录移到仓库之外使用。

## 原生桌面客户端（默认入口）

交互形态重构（docs/方案.md 第 2 节，F16）：技术栈决策为 WinForms 原生（docs/DECISIONS/D1-桌面技术栈.md），设计基线见 docs/DESIGN.md。双击 `ApifoxHelper.exe` 直接打开原生窗口，主工作流全程不嵌网页：项目设置（含连接与写入探测、模型服务、序列化与分析、配置导出）→ 新建任务与源码扫描（进度/取消）→ 注释缺口与代码证据 → 注释候选审阅（规则提取、模型生成、材料导入、手工填写）→ 注释回写或导出补丁 → 定向构建与生成文档核对 → 响应契约审阅 → Apifox 差异检查与差异确认 → 补充说明 → 同步预览、确认同步与回读核对 → 报告导出与前端交接。写入动作全部复用既有服务层的安全语义（计划哈希绑定、失败即停、部分完成如实显示），原生层只做预览与确认。

过渡壳按需回退：

```text
ApifoxHelper.exe --web
```

`--web` 打开此前默认的 WinForms + WebView2 过渡壳（内嵌网页，页面层已冻结、只修阻断性缺陷）。两个壳共用同一资料目录与本地服务。

构建与机械检查（Linux CI 可编译，Windows GUI 真机验证见 docs/NOTES.md 挂账）：

```text
dotnet build                  # 主工程（net8.0-windows 仅编译；Linux 由 csproj 内的条件属性启用）
dotnet test ApifoxHelper.Tests   # 令牌接线机械检查（DESIGN.md 与 UiTokens 逐值一致、界面代码无就地颜色/字体/间距值）与状态文案完备断言
```

## 桌面版

工具是一个 Windows 桌面程序：双击 `ApifoxHelper.exe` 打开原生桌面客户端（见上文）。`--web` 打开的过渡壳在窗口内用 Microsoft Edge WebView2 显示操作页面。页面与本地服务都在同一个进程里，关闭窗口即退出。

### 打包

```powershell
cd ApifoxHelper
.\publish.ps1                       # 自包含单文件：dist\win-x64\ApifoxHelper.exe，目标电脑不需要安装 .NET
.\publish.ps1 -FrameworkDependent   # 体积小的版本：目标电脑需要 .NET 8+ 桌面运行时与 ASP.NET Core 运行时
```

把生成的 `ApifoxHelper.exe` 发给使用者即可，无需安装；可以放在任意目录，或在桌面创建快捷方式。

### 使用者电脑需要

- 原生桌面客户端无额外界面依赖；`--web` 过渡壳需要 Microsoft Edge WebView2 运行时（Windows 11 自带，Windows 10 一般已随 Edge 安装；缺失时过渡壳窗口会提示）。
- Node.js 与 Apifox CLI：`npm install -g apifox-cli`，并在终端执行一次 `apifox auth login`。工具复用 CLI 的登录态，不收集令牌。
- 分析源码需要本机安装 .NET SDK（读取目标框架的参考程序集），被分析的项目最好已经 restore 过。

### 过渡壳窗口功能（`--web`）

- 菜单“文件”：在浏览器中打开、打开资料目录、打开日志目录、退出；“视图”：刷新、缩放、开发者工具；“帮助 → 关于”显示版本、资料目录和运行时版本。
- 下载报告、补丁时弹出“另存为”对话框。
- 同一资料目录只运行一个实例，再次双击会把已打开的窗口切到前台。
- 记住窗口位置和大小。
- 关闭窗口时如果有作业在执行（扫描、检查、同步等），会先确认；确认后请求作业在当前步骤结束后停止，最多等待 15 秒。正在写入的单个同步动作会完成并回读核对，不会中途打断。
- 页面只能访问本机服务地址，外部链接交给系统浏览器打开；内核缓存在资料目录的 `webview2` 文件夹，不保存密码和自动填充数据。

### 命令行参数

```text
ApifoxHelper.exe [--data <资料目录>] [--port <端口>] [--headless] [--web]
```

- `--data`：资料目录，默认 `%LOCALAPPDATA%\ApifoxHelper`（也可用环境变量 `APIFOXHELPER_DATA`）。
- `--port`：首选端口，默认 5179，被占用时自动换一个空闲端口。
- `--headless`：不打开窗口，只运行本地服务；从终端启动时输出访问地址，Ctrl+C 退出。用于自动化或 CI。
- `--web`：打开冻结的过渡壳（内嵌网页，仅供回退）；不带此参数即启动原生桌面客户端。`--native` 保留为兼容写法，行为与默认相同。

开发调试：`dotnet run --project ApifoxHelper/ApifoxHelper.csproj`。

## 使用流程

首次打开时，“检查任务”页会显示三步引导。任务页顶部始终显示三个阶段（源码注释 / 生成文档 / Apifox）和唯一的“下一步”，并在对应页签上标出圆点；任务列表也会列出每个任务的下一步，点击直接打开到那一页。

1. **项目设置**：常用项在上（仓库根目录、API 项目、允许回写范围、Swagger 与模块、Apifox 项目/分支），其余设置折叠，标题上显示当前取值。桌面版可以“浏览…”选择仓库目录；“查找 API 项目”会列出仓库中的 `.csproj`，Web 项目排在前面，只有一个 Web 项目时自动填入。保存后自动核对 CLI、登录与项目读取。
2. **检查任务**：点“新建任务”，选择配置与模块；“创建并扫描”会直接开始扫描源码注释（离线比较在“高级选项”里）。
3. **源码注释**：扫描注释缺口（不需要 Swagger，不执行 build/restore）；用“生成草稿”菜单中的规则提取、模型生成或“导出材料 → 编码助手处理 → 导入结果”得到候选。生成后自动切到“待审阅”，逐条查看代码证据后“接受并下一条”；覆盖率条下的标签可以点击筛选。
4. **注释补丁**：生成计划后可导出补丁，或确认后回写源码。只改 `///` 注释行；BOM、换行符、执行代码与预处理指令保持不变，确认后文件若被改动会拒绝写入。
5. **生成文档**：可选执行定向构建，然后核对注释在源码、XML 文档和 Swagger 中是否出现。
6. **响应契约**：确认通用封装中 data 的实际类型（静态追踪返回表达式与调用链）。
7. **Apifox 差异**：配置了 Swagger 时，首次检查会先加载并冻结 Swagger。逐项确认高风险变化、说明冲突、模型绑定与共享模型影响后“保存并重新检查”（确认要重新检查后才生效）；“全选可同步”勾选所有没有阻断、没有待确认项的变化接口，然后生成同步预览。
8. **同步**：确认计划后逐个写入并回读核对；可随时“重新核对（只读）”。
9. **报告**：下载 Markdown/HTML/JSON 报告与前端交接说明。

应用图标的母版在 `Assets/app-icon.svg`（32 px 及以上）与 `Assets/app-icon-small.svg`（16–24 px），`Assets/app.ico` 由两者逐尺寸渲染打包。

## 写入安全

- **源码写入**只发生在“确认应用注释”时，且只限“允许回写范围”内的 UTF-8 文件；每个文件写入前保存前态到本地任务目录。
- **Apifox 写入**默认关闭：当前 CLI 版本必须先在“项目设置 → 写入兼容探测”中，对专用测试接口通过往返验证（原样写回、临时改说明并恢复、整段写回参数/请求体/响应、导出与详情引用一致）。CLI 升级后需要重新探测。
- 同步计划绑定指纹：远端、Swagger 来源、补充说明或决策发生变化，计划即过期。写入超时不重发，先回读判断；首个失败即停止，部分完成如实记录，不自动回滚，不删除任何远端资源。
- 本地接口只监听 127.0.0.1，并校验 Host、Origin 与进程级会话令牌。

## 性能设计

- 远端概览用一次 `apifox export` 获取整分支接口与模型引用（实测 1075 个接口约 3 秒），只对范围内接口和模型逐个读取详情，读取并发可配置（默认 4），写入串行。
- 源码分析不运行 MSBuild：并行解析源码，语法树按文件大小与修改时间缓存复用，元数据引用缓存复用；只对选中接口做语义追踪，并有调用深度和方法数预算。
- 扫描、草稿生成、检查、计划、同步都在后台作业中执行，页面显示进度并可取消。
- 桌面版启动约 0.3–0.7 秒出现窗口（本机实测）；单文件发布启用压缩，体积约 78 MB。

## 本地资料

默认目录 `%LOCALAPPDATA%\ApifoxHelper\`：`profiles/` 配置、`mappings/` 模型映射、`baselines/` 同步基线、`tasks/<任务ID>/` 任务资料（扫描结果、证据、草稿、补丁、源码前态、检查结果、计划、执行日志、远端前后快照、报告）、`compat/` 写入探测记录、`credentials/` DPAPI 加密的模型服务密钥、`logs/` 运行日志（脱敏，保留 14 天）、`webview2/` 页面内核缓存、`desktop-window.json` 窗口位置。远端快照可能包含受保护配置，只保存在本机；共享报告已脱敏。

## 已知限制

- 项目加载只评估无条件或简单条件的 MSBuild 属性，不展开 Import、不运行源生成器；无法评估的部分在扫描警告中列出。
- 多实现 DI、反射、动态派发与外部程序集中的逻辑不展开，相关结论需要人工确认。
- 第一版只支持 OpenAPI 3.0.x JSON；不处理外部引用、`not`/`discriminator` 等结构，遇到时阻断相关同步。
- 本地锁不能阻止其他用户同时修改 Apifox；执行前的指纹核对仍存在竞态窗口。
