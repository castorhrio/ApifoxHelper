# 真机未验证的交互点：登记表

这一页是「哪些交互点还没在 Windows 真机上验过、未验证的是哪一层、连着几轮没验」的**唯一落点**。
判据有两条（第四百二十五轮起各自有自己的文件，判据本体共用一份）：`RealMachineInteractionGapTests.UnverifiedInteractionPoints_MustBeRegisteredWithLayer`
（下面「判据」那一节的行质量三条，本体在 `ApifoxHelper.Tests/RealMachineGapRegistry.cs` 的 `UnverifiedPointProblems`）与
`RealMachineGapCoverageTests.KnownLimitationScreens_MustBeRegisteredInTheGapTable`（第四百二十四轮起，
README「已知限制」点名的屏必须在这张表里有行，两侧对账）。抓不抓得住由两条门各自的注入验当场验：
`UnverifiedPointDetector_ReportsTheBreaksItMustCatch` 与 `GapCoverageDetector_ReportsTheBreaksItMustCatch`。

## 为什么要有这一页

第四百二十二轮给列表右键菜单补上了键盘入口（`Shift+F10` / 菜单键），那是**真机按键路由**这一层第一次有新代码。
而 `RealMachineSupplyGateTests` 此前只判「真机供给未读」的有界性（那一行写没写「现读」/「未读」、连着没读几轮），
**判不到「真机未验证的功能点」有没有登记**：一轮加了新交互、在条目里写一句「真机未验证」就过去了，
下一轮读的人分不清「这一层验过了」还是「从来没人验过」，也没有任何东西会红。

这一页补的就是那一格：**每一轮新增的真机未验证点必须登记，且必须写清未验证的是哪一层**。

第四百二十四轮补的是另一格：README「已知限制」里点名了多处「随 G-D5 复核」的屏（状态行「查看完整错误」入口、
提示对话框「复制路径」按钮、200% 档提示行、多显示器混合缩放、状态行「已取消」/「正在停止」两句），
这些屏的未验证状态 README 里挂了三十多轮的账，**这张表里却一处都没有**——行质量门管「表里有这一行」的纪律，
管不到「表里应当有哪些行」。本轮把那五处逐条登记（下表第 2–6 行），并立登记完整性对账门：
README 点名的屏集合 ↔ 这张表的行集合，两个方向都能红。

## 判据（三条行质量 + 一条覆盖，全部落在下面那张表上）

1. **未验证的是哪一层必须写清**：那一格只认三个词——`按键路由`、`弹出位置`、`观感`（多个用「、」分隔）。
   写「未验证」「待复核」这类含糊话即红：含糊话读不出「这一层到底量没量得到」，下一轮照样要重判一次。
2. **连续未验证轮次数必须能数出来**：那一格是整数，且必须等于「账本最新一轮 − 最近一次现读轮次」
   （从未现读过的，从首次登记轮次起算）。自己填一个数不算数——门按账本现算，填错即红。
   所以**每过一轮、这一格就要跟着重填一次**：第四百二十四轮右键菜单那一行从 1 改 2，就是这么来的。
3. **上限 3 轮，第 4 轮必须现读一次**：连续未验证超过 3 轮即红，那一轮必须真的跑一次读数
   （模拟器能覆盖的那一层跑模拟器、真机到手就跑真机），把读数写进「现读读数」那一格、计数归零。
   上限取 3 的理由与「真机供给未读」那条有界门同一分寸：三轮之内还看得出「上一轮判过什么」，
   再往后读的人只能看见一串「未验证」，分不清是判过了还是忘了。
4. **README 点名的屏必须在这张表里有行（第四百二十四轮起）**：README「已知限制」里**带着真机未验标记**
   （随 G-D5 / 真机复核 / 没量过 / 仍未验证 / 真机仍缺）的条目点名的屏，表里必须有行；反过来，
   表里 README 点过名的行，README 不再点名了（验完了）就必须删——两个方向都能红。
   对账走一张封闭词表（测试里的 `KnownLimitScreens`）：README 那几条是散文，屏名没有机械边界，
   词表把「哪些屏被点名过」钉成封闭集合。**代价要说清**：README 点名词表外的新屏，这条门看不见——
   所以点了名的那一轮必须同轮把新屏加进词表并补行，两处一处都不能省。

另外两条边界：**表不许为空**（0 行 = 这笔债被静默丢掉）；**首次登记轮次必须是账本里真有的那一轮，
且那一轮的条目里写着「未验证」**（登记一个从没承认过这件事的轮次，等于把登记变成自述）。

## 它不判什么

不判真机到底有没有到手（那是 `collect-real-machine.sh` 与 `docs/evidence/real-machine/` 的地盘），
不判 `G-D5` 那一格该不该勾（勾选框只由真机证据关闭），也不判「这一层该不该现在验」——那是排期，不是判据。
它判的只有一件事：**「哪些交互点还没在真机上验过、未验证的是哪一层、连着几轮没验」在仓里有一处可机械读的落点**。

## 登记口径（写这一页的人要守）

- **新增一行**：一轮加了新的真机未验证交互点，就在表里加一行，`首次登记轮次` 写当轮，
  `最近一次现读轮次` 写 `未现读`（除非当轮真的为这一层跑过读数），`连续未验证轮次` 按账本现算。
- **行的承认落点有两类**：README「已知限制」点名的屏（测试词表 `KnownLimitScreens` 里 `ReadmeAnchored`
  的那几处，即下表第 2–6 行）——存废跟着 README 走，验完了先摘掉 README 里的标记、再删行，同轮做；
  账本条目承认的新交互点（词表外，如第 1 行右键菜单）——`首次登记轮次` 写承认它的那一轮。
  两个落点各判各的方向，谁都不许静默消失。
- **过一轮，重填一次计数**：`连续未验证轮次` 那一格按账本现算（最新一轮 − 最近一次现读轮次），
  账本长出一轮它就跟着变——门现算对账，忘了重填即红。
- **现读一次**：真的跑了一次读数（模拟器或真机），把轮次写进 `最近一次现读轮次`，
  并在 `现读读数` 里写清**量到的是什么、量不到的是什么、是模拟器还是真机**——只写「已复核」不算读数。
- **验完了**：真机证据归档进 `docs/evidence/real-machine/` 之后，把这一行删掉（那一层不再是缺口），
  并在当轮条目里写清「哪一行因为哪一份证据被删」；README 点名的屏还要同轮摘掉 README 里的标记
  （两处同轮做，对账门两个方向各挡一边）。
