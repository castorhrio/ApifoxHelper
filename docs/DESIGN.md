# Apifox 助手：设计基线（唯一视觉来源）

版本：1.0（2026-11-07）
适用范围：阶段 D 的原生桌面客户端（F16）及此后所有界面改动。本文是界面视觉的**唯一来源**：界面代码的颜色、字号、间距、圆角只从本文的令牌表取值；改令牌必须同一次改动里更新本文与 `Desktop/Native/UiTokens.cs`，并说明理由。
依据：docs/方案.md §6（设计标准：继承来源与采用规则）、docs/功能清单与验收标准.md"设计验收"D1–D14、docs/DECISIONS/D1-桌面技术栈.md（技术栈与已知代价）。
继承规则：灰阶铬色沿用本产品过渡页（`Web/app.css`）已验证的取值，保持视觉连续；强调色按方案 §6.2 #2 为本产品语境自选，不抄任何兄弟产品色值。

## 1. 原则

1. 灰阶铬色 + 恰一个强调色。强调色只出现在主行动与焦点；无渐变、无玻璃拟态、无阴影、无框架默认观感直接交付。
2. 状态一律"颜色 + 文字"双通道；错误/风险用文字色，不铺大面积色底；灰度打印仍可读。
3. 每屏只有一个实心主按钮；其余 ghost；"停止"类为 ghost + 危险字色且位置尺寸不变。
4. 不可逆或破坏性动作（执行同步、覆盖式写入、退出确认）用原生确认对话框；常规校验内联展示，不弹窗。
5. 空态不留白；失败与截断如实显示；"部分完成""结果不确定"不显示成全部成功。
6. 中文单语；按钮用动词；状态说结果不说机制；错误给下一步；不用空话（赋能/闭环/一站式/无缝/智能…）；不向用户自述工程进度。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `Bg` | `#F5F7FB` | 窗口背景 |
| `Panel` | `#FFFFFF` | 面板、输入框、列表底色 |
| `Line` | `#E3E8F0` | 1px 发丝边：分隔线、输入框与 ghost 控件描边 |
| `Text` | `#1F2937` | 正文、控件文字 |
| `Muted` | `#6B7280` | 次要说明、标签、禁用文字（禁用另加 50% 不透明度观感由控件态表达，不改色值） |
| `Nav` | `#111827` | 左侧导航底色（深灰铬，延续过渡页） |
| `NavText` | `#E5E7EB` | 导航文字 |

| `WarnText` | `#B45309` | 警示、待确认、"部分完成"的**文字**色 |
| `BadText` | `#B91C1C` | 错误、失败、阻断、停止按钮的**文字**色 |

## 3. 字号档（封闭四档）

档位按 96dpi 逻辑像素记录；WinForms 以磅落码，换算 = 像素 × 0.75。不得新增第五档；确需扩档先改本文，严格递增、无死级别、每级有使用点。

| 档 | 像素（磅） | 行高 | 使用点 |
| --- | --- | --- | --- |
| Caption | 12px（9pt） | 18px（行距 1.5） | 辅助说明、表头、状态行、标签 |
| Body | 14px（10.5pt） | 22px（正文行距 1.55） | 正文、输入框、列表行、按钮 |
| Section | 20px（15pt） | 30px | 分区标题、页标题 |
| Title | 28px（21pt） | 40px | 首屏大标题（如空态引导） |

字体栈（有序，找到即停，全不匹配回退系统字体；刻意排除衬线中文字体）：Segoe UI → Microsoft YaHei UI → Microsoft YaHei → SimHei。
等宽栈（计数、进度、ID、路径、差异文本必须等宽）："Cascadia Mono" → Consolas → Courier New → monospace。
中文排版附加条款（审查 D10）：全角标点；行首行尾禁则；正文容器 ≤45em；字距非负；禁假斜体；中文引用只用「」；中英文之间留一个半角空隙。

## 4. 间距（封闭五档，4px 基准）

| 档 | 值 | 语义 |
| --- | --- | --- |
| `Xs` | 4 | 图标与文字、行内元素之间 |
| `Sm` | 8 | 控件组内间距、列表行内边距 |
| `Md` | 12 | 相关联控件之间、面板内边距（紧凑区） |
| `Lg` | 16 | 面板内边距、分区之间 |
| `Xl` | 24 | 页面级留白、分区标题与内容之间 |

组件内不得出现档外数值；表格密集屏确需扩档先改本文。

## 6. 控件形态

| 控件 | 形态 |
| --- | --- |
| 主按钮（每屏至多一个） | `Accent` 实心填充 + 白字，无描边；hover 只改底色（加深一档，无位移/缩放/阴影）；禁用 = `Line` 描边 + `Muted` 字 |
| Ghost 按钮 | `Panel` 底 + 1px `Line` 描边 + `Text` 字；hover 底色变 `Bg` |
| 停止/危险 | Ghost 形态 + `BadText` 字色；位置尺寸与常态一致（防按钮跳位） |

第三十三轮）——列表重建后方向键从选中项继续、不跳回首行，程序化选中不得绕过该入口；两个主页面的列表在重建（页面切换、刷新、保存对话框返回）后按既有选中恢复，任务页自第一轮起如此，项目配置页补齐于第三十四轮（此前任何重建后选中丢失、「编辑/连接与写入探测」退回禁用）；列宽：标识列（首列）吸收剩余可视宽度（`ListColumns` 单一口径，2026-11-07 第三十七轮）——列合计对齐可视宽度，正常窗口宽度不出横向滚动条（此前固定像素列宽合计 872/880px，默认窗口下「更新时间」等列尾列被横向滚动条藏住）；窗口放不下固定列合计时首列回退设计宽度、横向滚动条如实出现；任务页列表与详情的分割（2026-11-07 第三十八轮）：详情区保持 420 设计宽（`FixedPanel = Panel2`），窗口缩放时列表吸收剩余宽度——与标识列吸收剩余可视宽度同一方向（FixedPanel 缺省 None 会让详情区随窗口按比例放大、偏离设计宽）；分割距离在首次显示时按可行性门控设置（详情设计宽 + 列表下限 + 分隔条宽），壳最小窗口宽度（分割面板约 776px）下同样成立，不停留在 WinForms 默认的 50px（此前门控「宽度 > 800」在此恒假，任务列表只剩一条缝）；双击激活（2026-11-08 第三十九轮）：双击只在命中行时打开该行（`Ui.ActivateItem` 唯一入口，MouseDoubleClick + HitTest 守卫）——`ListView.DoubleClick` 不区分命中行，双击空白区不动作（此前配置列表双击空白区会借清空后的空选中打开「新建配置」对话框）；「查看代码证据」双击快捷方式（候选审阅与注释缺口两对话框）同经此入口——命中哪行看哪行的证据（行自身载荷，按钮与双击共用一份行内门控），双击列头与空白区不动作，清空选中时证据按钮如实禁用（2026-11-08 第四十轮收口：此前候选审阅对话框清空选中后按钮残留启用、点击无响应）；列排序（2026-11-08 第四十七轮）：两个主页面列表点击列头即按该列排序，同一列再点反向、换一列从升序开始，排序列表头带方向标记（▲ 升序 / ▼ 降序）、其余列回到原标题——由 `ListSort` 单一口径落地，标记字面不得在两页就地拼写（标题取自建列时快照，每次按原标题重算，反复刷新不叠加）；未排序时保持数据源自身顺序（任务=创建时间倒序、配置=名称升序）；排序状态留在本页，刷新、作业结束与切页回来后的重建按同一列同一方向呈现；排序状态跨启动记忆（`ListSortMemory` 单一口径，2026-11-08 第五十五轮，与「启动回到上次使用的页面」「窗口位置」同族的会话型便利设置）：按**列标题**记下本页上次排的列与方向，下次启动回来仍是这一列——记标题不记列号，因为界面增删列后列号会指向另一列，那等于把用户没点过的那一列当成上次排的那一列；认不出标题（列删掉、文案改动、内容损坏、无记录）一律回退数据源顺序，方向位一并归零，不猜相邻列（与「列表 Ctrl+C 复制标识列」的「声明列落在格数之外时宁可复制不到」同一取舍）；只记这一件事——不记筛选关键词（把关键词带进下次启动会把行藏起来，而筛到零行的下一步是空态的「清空筛选」）、不记选中行、不记列宽列序，也不写任务与配置数据；排序只改呈现顺序——不写任务与配置数据、选中按 Id 恢复、同值行在两个方向都保持数据源顺序（反向不把手风琴里同值的行打乱重排）；排序键与单元格取值同源：文字列按自然序比较（数字段按数值、「2」在「10」前，与资源管理器名称列同序；其余段仍按当前区域比较、不按码位排——2026-11-08 第五十四轮收口第四十七轮挂账的「数字 ID 列按文字排序」，任务名/配置名/接口资源/项目 ID 常带序号，纯文字比较会把「报告10」排到「报告2」前）、数量列按数值、时间列按完整时间戳而非单元格显示到分钟的文字；Enter 打开选中行（2026-11-08 第五十一轮）：配置页列表在行上按 Enter 打开该行的编辑，与双击共用同一条回调、同一个 `Ui.ActivateItem` 唯一入口（`byEnter` 按需接线）——键盘入口以焦点行为准，焦点行缺失即不动作，不得借当前选中做出与鼠标不同的事（与第三十九轮「命中哪行激活哪行」同一纪律）；裸 Enter 判定取 `ListKeys` 单一口径，带 Ctrl/Alt/Shift 的组合不吞键；对话框不接（窗体设了 AcceptButton 时 Enter 在控件收到按键之前就被窗体的对话键处理取走，本行「对话框 Enter=确认」的既有语义保持），任务页列表没有「打开该行」这一步（选中即出详情）故也不接，不为它发明动作；Ctrl+C 复制焦点行的标识列（2026-11-08 第五十二轮装上，标识列口径于第五十三轮收口）：单元格自绘后文字不可选中，而原生界面此前没有任何把文字交给用户的通路（无剪贴板入口、无右键菜单，只有只读预览框可选），「GET /路径」这类只在检查结果/补充说明/同步预览/契约清单首列出现的接口身份只能肉眼抄进新建任务的「指定接口」——按资源管理器「Ctrl+C 复制选中项名称列」的既有手势补上，装在 `Ui.List` 工厂一处（整个原生界面的剪贴板只在此触达一次，页面与对话框不各写一套，也不为列表加控件、加颜色、加提示）；复制的是焦点行**标识列**的原文（`ListCopy.CopyText` 单一口径：不拼其余列、不裁剪、不改写——粘贴出去的就是看到的那一格）；标识列默认首列（与本行「列宽」的『标识列（首列）』同一约定，绝大多数列表的名称格就在首列），首列不是名称的列表在 `Ui.List(identityColumn:)` 出厂处声明真正的名称格（2026-11-08 第五十三轮）——同步预览「写入清单」的首列是动作序号（第几步，认不出这一行写的是哪个接口或模型）、差异确认清单的首列是「接口/模型」分类（许多行同值），两者的名称格都在「资源」列；声明的列必须落在该行实际格数之内（`ListCopy.IdentityColumn` 单一口径），列被增删而声明没跟上时这一行没有可交出去的一格：不动剪贴板，更不把邻列的文字当成名称抄出去（粘进「指定接口」的错东西比复制不到更难发现）；声明与列序的对应由用例机械钉住（常量值 = 该列表里「资源」列的实际位次、声明点只在这两个文件——其余列表一律走默认首列，新增声明须先说明首列为什么不是名称）；以焦点行为准且该行处于选中态，焦点行缺失、未选中或标识列无文字一律不动作，更不把用户先前复制的内容抹掉（与第三十九轮「命中哪行激活哪行」、第五十一轮「焦点行缺失即不动作」同一纪律）；裸 Ctrl+C 判定取 `ListCopy` 单一口径，带 Shift/Alt 的组合不吞键；剪贴板被其他进程占用时本次没有复制，不重试、不弹窗、不谎称已复制；审阅队列的选中续接（2026-11-08 第五十六轮）：逐条处理的三个审阅视图（注释候选、响应契约、差异确认）停在「待审阅/待确认/待处理」筛选上清队列时，刚处理的那一条不再属于当前筛选、从清单上消失——此时选中落到**接替他位置的下一行**（原显示第 N 行，重建后第 N 行就是他的下一行；本来在末行则落到上一行；一行不剩则没有落点，不借第一行、不选中不存在的一行），取 Outlook/资源管理器「删除或归档当前项后选中相邻下一项」的既有惯例；**不回跳队首**（每保存一条都要重新找位置），也不丢选中（选中一丢详情区与审阅按钮随之清空，只能回鼠标点下一行）；落点由共享口径 `ListAdvance` 的 `IndexAfterRemoval` 给出（不依赖 WinForms；旧清单上本来就没有选中时从队列开头继续——切换筛选与打开时的落点仍是新筛选第一条，那一行没有「刚处理的一条」），触达界面只在 `Ui.AdvanceAfterRemoval` 一处、选中仍经本行既有唯一入口 `Ui.SelectItem`（Selected + Focused 一起恢复，方向键从该行继续）；被处理行的显示序号在保存动作之前记下（await 期间用户可能移动选中，之后取的就是别的行的位置）、清单重建之后才判落点；只改选中落点——不改审阅状态、不写任务数据、不重建清单（重建仍由各视图自己的入口做），主页面列表按 Id 恢复选中的口径（第三十四轮）与只读清单不受本轮影响；**选中即定位**（`ListReveal` 单一口径，2026-11-08 第五十七轮）：程序化选中在 Selected + Focused 之后把该行滚入可见区——清单重建（刷新、切页、筛选、保存对话框返回、处理完一条续接下一条）会把滚动位置甩回顶部，落在屏外的选中不是定位：详情与审阅按钮跟着那一行走，屏幕上却看不出自己在哪，方向键也从一行看不见的行继续（第三十三轮的焦点标记、第五十六轮的续接落点都要靠这一步才在长清单上成立）；滚动只在 `Ui.SelectItem` 唯一入口触达一次，页面与对话框不各写一套（第五十一轮曾在两页各补一句 `item.EnsureVisible()`，本轮收进入口，其余十二处选中此前无人管），是否请求滚动由 `ListReveal.ShouldReveal(index, displayedCount)` 判定——序号在本清单行数之内才动，行已离开控件（`ListViewItem.Index` 未加入清单即 -1）、空清单、序号越过末行一律不动作：框架的 `ListView.EnsureVisible` 对越界序号在检查窗口句柄之前先抛 `ArgumentOutOfRangeException`（已核对官方源码），本环境无原生运行时可跑，宁可少滚一次也不让一次选中变成崩溃；只改可见位置——不写任务与配置数据、不改审阅状态、不改选中归属与落点数学（`ListAdvance` ## 7. 状态表模板（每屏必交）

每屏按此表逐态定义控件可用性与文案；空态不留白，失败不装干净。

| 态 | 要求 |
| --- | --- |
| 空态 | 说明"现在有什么可做"+ 唯一行动按钮（按钮按状态切换：没有数据=新建、筛到零行=清空筛选；形态与口径见 §6「空态」行）|
| 加载 | 状态行文案 + 主行动禁用 |
| 执行中 | 进度 + 可取消（停止为 ghost + 危险字色）；主行动隐藏或禁用 |
| 错误 | `BadText` 文字 + 下一步指引；不铺色底 |
| 禁用 | 控件禁用 + 一句话说明缺什么——因「没有选中那一行」而禁用的，那句话由该屏的详情区说（见 §6「列表行」的「未选中那一行的那句话」）；「筛到零行」与「整份数据不可得」两种空仍由提示出口说（见 §6「列表筛选」），详情区不抢那两态 |
| 部分完成/中断 | `WarnText` 标签 + 如实数字，不显示成全部成功 |
