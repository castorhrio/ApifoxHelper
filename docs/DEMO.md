# 3 分钟演示：从零到「看到缺口被工具找出来」

这一页是**演示剧本**，不是新功能说明。它只做一件事：把主链路按 `README.md`「使用流程」已有的那几站串成一条 3 分钟能走完的路，
让第一次看这个工具的人在三分钟内看到**工具自己找出来的缺口**，而不是听人念功能清单。

**演示分两段：第 1–6 站全程不连 Apifox（离线），演示不执行远端写入；第 7 站要一台真的连得上 Apifox 的项目才走得到。**
这是 `docs/方案.md` §8 那条写入安全不变量在演示路径上的落点，也是第三百四十三轮把剧本逐站与产品实物对过之后如实改写的结论：
**离线任务在产品里不能生成同步预览**——`Sync/SyncPlanService.cs` 的 `CreateAsync` 第一句就拒绝（「离线检查不能同步。」），
任务页那颗「同步预览」对离线任务是禁用的（`Desktop/Native/TasksPage.cs`）。产品自己也把这条边界念在屏上：
检查跑完之后，三个阶段那一行的「Apifox」格念的是**离线检查**（`TaskDisplay.RemoteStatusText`），
下一步横幅念的是标题**「离线检查完成」**、说明**「离线比较不能同步；可以查看差异或下载报告。」**（`Desktop/Native/NextStep.cs` 的 `offline` 那一支）。
现场没有 Apifox 项目时，演示到第 6 站为止，把工具那两句如实的话念出来，不硬凑第 7 站。

## 演示前的一次性准备

1. 打开桌面客户端（`dotnet run --project ApifoxHelper.csproj`，或已发布的 `ApifoxHelper.exe`）。
2. 演示工作区在仓库里：`samples/demo-workspace/`。它只有四个文件——
   `Demo.Api.csproj`、`Controllers/OrdersController.cs`、`Models/OrderSummary.cs`、`apifox-remote.json`。
   没有 `bin/`、没有 `obj/`、没有任务目录：**从零开始**，不是某台机器上的残留。
3. 演示工作区里**故意留了两处差异**，但这两处在演示里**不是同一眼就能看到的**，如实分开念：
   - **缺口 ①**：`OrdersController.ListOrders` 没有 `///` 注释（`GetOrder` 有，对照着看）。
     这一处**离线就能看到**，是第 3 站的主角。
   - **缺口 ②**：`OrderSummary.TotalAmount` 的源码注释写「单位：元」，而 `apifox-remote.json` 里同一字段写「单位：分」。
     这一处**离线比不出来**：产品把源码说明与远端模型说明摆在一起比的那一段（`Sync/CheckService.cs` 的 `CheckModels`）
     **只在非离线任务里执行**，离线检查连模型清单都不生成。要看它，得连上真实 Apifox 项目走第 7 站那一段；
     现场不连 Apifox 时，第 6 站念的是检查结果问题区那一句「离线检查：只比较结构，无法证明 Apifox 原生设置、重复接口与线上状态，同步不可用。」，不是「比出了一处冲突」。
4. 远端不用连：`apifox-remote.json` 是一份 OpenAPI 快照，演示时经「导入离线远端 JSON」读入，走的是产品已有的离线路径。
   代价写在上面第 3 条那一句里，这里补全：**离线路径同步不可用、模型说明不比对**；结构差异要有可比的对象，
   还得多一步把 Swagger 冻结下来（`Sync/CheckService.cs` 里没有冻结副本、又是离线任务时，接口那一头不构造目标）。
   第三百四十三轮真跑一遍量到的正是这一屏：两行接口都是「无变化」，问题区只有那句离线边界。

## 演示时要说清的三句话

- **缺口 ① 是工具找出来的，不是我准备好的**：它由扫描器报出（`SourceScanService` 的注释位置清单），
  第 3 站到第 5 站那条回写链全程不靠人翻代码。
- **缺口 ② 这一处不冒充已看到**：源码说「元」、快照说「分」这两句话确实不一致（`ApifoxHelper.Tests/DemoWorkspaceTests.cs`
  逐字读过两边钉着），但**产品把两类说明摆在一起比的那一段只在连上 Apifox 时才跑**——离线演示里它比不出来，
  现场要么连上项目再念，要么如实说「这一处今天不演示」。
- **不配模型服务也能走完第 1–6 站，但第 4 站靠的不是规则提取**：第三百四十七轮在 wine 里真跑过一遍——规则提取在这三处缺口上产出 **0 条**，界面当场把原因念出来（方法用途说明、没有校验特性的查询参数、没有响应契约的返回值，规则一概不生成）；离线走完第 4、5 站用的是产品自己给出的那一条路：**「查看注释缺口」→「手工填写说明」→「添加为候选」→「接受并下一条」**。第 6 站用的是离线快照。这六站全程不联网、不调模型服务。
