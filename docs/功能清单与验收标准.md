# Apifox 助手：功能清单与验收标准

版本：1.1（2026-11-07）
配套文档：docs/方案.md（产品定义、状态标注约定、交互形态重构定义、对比规则、写入安全边界、设计标准继承）。

本文对方案第 7 节功能地图中的每项功能给出标准化说明：**状态、用户价值、输入、输出、用户操作、状态与异常、可验收示例**。示例均为解释产品行为的假设场景，不指向真实项目；未标注"已验证"的示例描述的是设计目标，验收时须实际执行。

约定：

- "源" 指冻结的 Swagger 加已确认响应契约与说明条目构造的目标；"远端" 指 Apifox 项目/分支中的当前内容。
- 文中"页面/页签/保存并重新检查"等措辞是**工作流级界面单元**的名称，不绑定实现：交互形态重构（方案第 2 节）后由桌面客户端的原生界面承载同样的工作流与确认点。
- 验收分为"功能验收"（行为符合本文）与"链路验收"（对真实 Apifox 执行）。标注【待验证】的条目依赖写入链路真实运行，接受前不得宣称完成。

---

## F01 项目配置与目标绑定

**状态**：已实现（已验证：配置保存、CLI/登录/项目读取核对、模板提取）。

**用户价值**：把仓库、Swagger 来源、Apifox 目标三者绑定成可复用配置，避免每次手填。

- **输入**：仓库根目录、API 项目（.csproj）、允许回写范围、Swagger 来源（文件/URL/无）、模块名与路径前缀、Apifox 项目 ID 与分支、新接口目标目录与模板来源接口、CLI 的 node/cli.js 路径（可选，默认自动定位）、质量检查开关。
- **输出**：持久化配置（不含任何令牌）；"保存后核对"结果：CLI 版本、登录状态、项目可读性。
- **用户操作**：浏览目录、"查找 API 项目"、选择项目/分支/目录、从既有接口提取模板、保存并核对。
- **状态与异常**：node/cli.js 缺失、CLI 未登录、项目不可读分别给出可操作提示；Apifox 项目 ID、分支与业务项目上下文是三个独立字段，不得混用。
- **可验收示例**：新机器上只安装 Node.js、apifox-cli 并完成 `apifox auth login` 后，10 分钟内完成一份配置并通过"保存并核对"；故意填错 CLI 路径时得到明确报错而非静默降级。

## F02 写入兼容探测与能力门禁

**状态**：已实现（待验证：探测流程从未真实运行）。【待验证】探测通过后的写入放行。

**用户价值**：在把任何内容写进 Apifox 之前，用真实往返验证当前 CLI 版本不会丢内容、不会破坏受保护设置。

- **输入**：专用测试项目 ID、测试接口 ID、分支（默认主分支）、用户确认勾选。
- **处理**（探测五步，任一步失败即记录并整体判不通过）：读取测试接口 → 分支隔离检查（测试接口必须出现在指定分支列表中）→ 原样写回说明并回读 → 临时修改说明再恢复并回读 → 整段写回参数/请求体/响应并回读 → 导出概览与详情的模型引用一致性。
- **输出**：按 CLI 版本登记的探测记录（逐项通过/失败与详情）；能力接口返回"当前 CLI 版本是否允许写入"。
- **用户操作**：在项目设置中填测试目标、确认执行、查看逐项结果。
- **状态与异常**：探测会临时修改测试接口（结束时恢复），必须显式确认；未通过探测的 CLI 版本，F12 拒绝生成同步计划；CLI 升级后旧记录失效，需重新探测。
- **可验收示例**【待验证】：对一个专用测试接口执行探测，全部检查项通过；把该 CLI 版本的记录删除后，尝试生成同步计划被拒绝，提示先探测。

## F03 源码扫描与注释缺口检查

**状态**：已实现（已验证）。

**用户价值**：不依赖 Swagger、不执行 build/restore，定位接口方法、参数、请求/响应 DTO、枚举上缺失或失效的注释。

- **输入**：任务绑定的配置快照与模块范围；工作区当前文件状态（含未提交修改）。
- **处理**：无构建加载项目与引用 → 发现范围内接口 → 追踪响应 data 实际类型 → 生成注释位置清单（方法 summary/returns、每个入参、DTO 属性、枚举成员）→ 收集代码证据（路由、调用、校验、守卫、查询过滤、映射、返回分支）→ 判定每个位置状态。
- **输出**：接口清单、注释位置清单（状态：缺失/空标签/失效 param/未解析 inheritdoc/有效）、证据列表（文件、行号、片段）、覆盖率统计、未解析符号与外部类型清单、扫描警告。
- **用户操作**：点"创建并扫描"或"扫描注释"，查看进度并可取消。
- **状态与异常**：引用不完整、条件编译未展开、动态派发/多实现 DI/反射不展开——列入扫描警告与未解析清单，明确降级，不按同名猜实现；扫描中断不产出半份结果。
- **可验收示例**（已验证场景）：对注释不全的控制器模块扫描，方法 summary 缺失、参数无 `<param>`、DTO 属性无说明、空 `<summary></summary>`、参数改名后的失效 `<param>` 分别被列出并附代码位置；响应为通用封装的接口追踪出 data 具体类型。

## F04 注释草稿生成与审阅

**状态**：部分实现（规则提取、材料文件交换、手工填写可用；模型服务代码完成、无真实服务密钥验证）。

**用户价值**：为缺口位置生成有代码证据的中文注释候选，人工逐条审阅，不编造业务含义。

- **输入**：选中的注释位置；生成方式（规则提取 / 模型服务 / 材料导出+结果导入 / 手工填写）。
- **处理**：四种入口共用同一候选格式。规则提取只生成代码可证实的约束（校验特性、默认值、守卫条件、枚举显示名、响应 data 类型），不生成方法/类型用途语义；模型服务只发送用户确认范围的材料，候选必须引用本次扫描中存在的证据编号，无证据结论只能进"需业务确认"；候选与证据指纹绑定，代码变化后标记过期要求重新审阅。
- **输出**：候选列表（文字、证据编号、待确认问题、来源、审阅状态）；已接受候选集合（供 F05 回写、F09 目标构造共用，避免三处手填含义漂移）。
- **用户操作**：逐条查看代码证据 → 修改或接受 → "接受并下一条"；可批量接受已逐条审阅过的项；未配置模型时其余入口照常可用。
- **状态与异常**：模型服务不可达、超时、返回不合法 JSON 时如实报错，扫描与手工补全不受影响；证据过期的已接受候选自动转为"待重新审阅"；没有生成结果的运行记录为"无结果"，不冒充成功。
- **可验收示例**：规则提取对带 `[Range(1, int.MaxValue)]` 的参数生成"必须大于 0"并附校验代码位置；对只有参数名、无任何证据的参数不生成事实性说明，只留待确认问题；接受候选后修改对应代码再扫描，该候选显示为过期。

## F05 源码注释应用与补丁导出

**状态**：已实现（已验证）。

**用户价值**：把审阅通过的注释安全写回源码，或导出补丁交给他人处理；绝不触碰执行代码。

- **输入**：已接受的候选集合；当前工作区文件。
- **处理**：生成仅含 XML 文档注释改动的计划 → 展示路径、符号、旧/新注释 → 应用前重读文件指纹（变化则 409 拒绝）→ 只在注释行内编辑：正确转义 XML 特殊字符、保留缩进/BOM/CRLF-LF、删除失效 param、不动属性、语句、预处理指令 → 逐文件写入并保存前态。
- **输出**：回写结果（成功/跳过/失败逐文件）；可导出的 `.patch`（与回写逐字节一致）。
- **用户操作**：预览源码差异 → "确认应用"，或"导出补丁"。
- **状态与异常**：允许回写范围之外的文件、生成代码、定位不明确的符号不修改；应用后文件被外部修改时以本地前态供人工恢复，不自动覆盖。
- **可验收示例**（已验证场景）：对 CRLF+BOM 与 LF 两类文件回写后格式与换行符不变，`#if` 块与其他注释不动；导出的补丁用 `git apply`（关闭 autocrlf）得到与回写逐字节相同的结果。

## F06 生成文档与传播核对

**状态**：已实现（已验证：只读核对与构建参数预览；定向构建需用户确认）。

**用户价值**：确认注释真的进入了 XML 文档和 Swagger，旧生成物不算已生效。

- **输入**：已接受候选；工作区项目（GenerateDocumentationFile、XML 路径）；当前 Swagger 来源。
- **处理**：重新加载源码 → 逐条核对三个环节：注释是否写到目标符号（written/notWritten/符号不存在）→ 是否出现在实际 XML 产物（present/different/missing/noXml/disabled）→ 是否被 Swagger 渲染到正确位置（present/different/missing/notRendered/unavailable）。XML 比源码旧时明确提示产物过期。
- **输出**：逐条传播状态 + 项目 XML 文件状态 + Swagger 信息；定向构建命令预览与执行结果（可选，用户确认后执行）。
- **用户操作**：点"传播核对"；需要时确认执行定向构建后重新核对。
- **状态与异常**：没有已确认候选时提示无可核对内容；工具默认不构建、不 restore；报告区分"源码已完成，生成文档未验证"。
- **可验收示例**：回写注释但未重新生成 XML 时，核对结果逐条显示"源码已写入、XML 缺失/过期"，不显示为完成；用户执行定向构建并刷新 Swagger 后重新核对，对应条目转为"已进入 Swagger"。

## F07 响应契约补全

**状态**：已实现（已验证：只读追踪真实项目接口）。

**用户价值**：通用封装 data 为 object 时，给出逐接口的实际响应结构候选，经确认后进入目标文档。

- **输入**：接口方法的返回表达式、封装构造、被调用服务签名。
- **处理**：追踪 return 表达式与调用链，收集各分支（成功/业务失败）的 data 形状 → 结合序列化名称与忽略规则得出对外字段 → 生成逐接口候选契约（data 类型、分支、证据、源码指纹）。
- **输出**：响应契约列表（候选/已确认/已拒绝/已阻断/已过期）；确认后的契约在 F09 中替换目标 200 响应体。
- **用户操作**：在"响应契约"页签查看追踪结果与证据，确认或驳回。
- **状态与异常**：存在未解析点或多个形状的契约不能确认（阻断）；源码变化使确认过期并要求重新审阅；确认只增强该接口文档，不全局修改共享封装；动态对象、匿名返回等不可靠场景保留人工确认。
- **可验收示例**（已验证场景）：控制器返回通用封装、服务返回 `List<T>` 的接口被追踪出 data 具体类型；确认后检查结果中该接口 200 响应体展示具体字段，且质量检查的"通用响应缺少具体 data 类型"消除。

## F08 Apifox 远端读取与快照

**状态**：已实现（已验证：真实项目只读检查）。

**用户价值**：建立可靠的远端现状视图，支持重复身份、悬空引用与共享模型影响分析。

- **输入**：配置中的 Apifox 项目 ID、分支。
- **处理**：读取接口总数 → `export` 一次取得整分支接口树与模型引用（导出文件解析后立即删除，只保留引用概览）→ 对范围内接口与被引用模型（含递归引用）按配置并发逐资源读取详情。
- **输出**：分支概览（接口：ID/方法/路径/名称/目录/模型引用；模型：ID/名称/引用；目录树；完整性与问题清单）；范围内接口与模型的权威详情。
- **用户操作**：随"契约检查"自动执行，无独立操作。
- **状态与异常**：列表总数与导出数不一致 → 概览标记不完整，阻断模型更新与同步计划；详情读取失败不按"不存在"处理；`schema list` 无分页已适配；悬空引用与重复身份进入问题清单。
- **可验收示例**（已验证场景）：千级接口分支约 3 秒完成概览；人为构造同路径同方法的两条远端接口后，检查结果将该身份标为阻断并列出全部候选 ID，不任选其一覆盖。

## F09 契约检查与差异展示

**状态**：已实现（已验证：真实项目只读检查与差异计算）。

**用户价值**：把"源 vs 远端"的差异精确到字段位置，区分结构变化、说明合并结果与质量问题，标出风险。

- **输入**：冻结 Swagger、已确认响应契约、说明条目（已确认注释/源码已有注释）、人工补充与决策、远端快照与详情。
- **处理**：构造本次目标 → 与远端逐接口比对（参数、请求体、各响应码；模型属性、required、引用；嵌套与数组；递归用已访问集合防环）→ 风险分级（区分请求/响应方向）→ 说明合并（规则见方案 4.5：人工补充 > 已确认注释 > 源码已有注释 > Swagger；已有说明默认保留；已确认注释与远端不同形成冲突待选择；接口标题默认保留远端）→ 质量检查（缺标题、参数缺说明、响应字段缺说明、通用响应缺具体 data 类型、阻断项）→ 模型检查（映射状态、候选绑定、新建模型递归阻断、共享模型影响范围）。
- **输出**：逐接口检查结果（状态：新增/结构变化/说明变化/无变化/阻断/仅源码）+ 差异条目（位置、旧值、新值、来源、风险、原因、是否需决策）+ 模型清单 + 质量问题 + "远端有、源中没有"清单。
- **用户操作**：在"Apifox 差异"页签按模块/类型/风险筛选；逐项查看字段对比；对高风险变化逐项确认或排除；对说明冲突选择保留远端或使用目标；对模型候选确认绑定；处理后"保存并重新检查"（保存会递增任务版本，使旧检查与旧计划过期）。
- **状态与异常**：未提供 Swagger 时结构保持远端现状只合并说明并明确标注；离线比较时同步禁用；不支持的结构（外部引用、not/discriminator 等）阻断相关接口而不静默跳过；读取失败不当作空结果。
- **可验收示例**：源新增必填 query 参数 → 该接口状态"结构变化"，差异条目注明位置 `query.x`、风险"潜在不兼容"、需逐项确认后才能进入计划；共享模型新增响应字段 → 模型条目列出范围外受影响接口，概览不完整时该模型更新被阻断。

## F10 说明与场景维护（含示例补充）

**状态**：部分实现（人工说明、场景、示例补充可用；自动生成示例待实现）。

**用户价值**：把代码推不出来的使用场景、参数含义、响应含义、示例补进文档，且不覆盖他人维护的已有内容。

- **输入**：接口/模型/字段定位；说明文字；示例（须为合法 JSON）；"保留现状"选择。
- **处理**：补充按"资源 + 位置 + 字段"精确定位；保存时未变化不递增任务版本；补充内容进入 F09 的目标构造，随计划写入；未填写的说明留在本地待办，不把"待确认"等草稿文字发布到 Apifox。
- **输出**：补充存储；目标文档中对应位置的说明/示例；报告中"人工确认后保留现状/未补充"统计。
- **用户操作**：在差异详情的说明编辑区填写场景、参数规则、响应含义、示例，或选择"保留现状，本次不补充"。
- **状态与异常**：示例不是合法 JSON、说明超长时拒绝保存；字段移除后其旧说明不迁移；类型或约束变化使已有示例标为需复核，失效示例不自动发布。
- **可验收示例**：为查询接口补"使用场景：对账页导出前预览；ArchiveId 与 ClientId 互斥"后，该文字出现在最终预览与回读核对中；已有接口说明在本次未编辑时保持不变。

## F11 共享模型绑定与影响分析

**状态**：已实现（已验证：只读影响计算；写入效果待 F02 探测通过）。

**用户价值**：改一个共享模型前知道全部影响面，防止误伤范围外接口。

- **输入**：目标模型（源组件名）；远端分支概览；已有映射与本次绑定决策。
- **处理**：同名唯一生成绑定候选，确认后持久化"源组件名 → 远端模型 ID"；影响分析沿引用图正反向遍历（防递归死循环），列出范围内/范围外受影响接口；概览不完整时阻断模型更新；新建模型相互递归引用时第一版不自动创建（需要预建空壳），要求人工准备。
- **输出**：模型检查条目（映射状态、候选、依赖、影响范围、阻断原因）；模型动作（新建/更新，按依赖顺序排在接口之前）。
- **用户操作**：在模型区确认首次绑定（绑定远端已有 ID 或选择新建）；确认范围外影响。
- **状态与异常**：候选不唯一或名称相近不自动绑定；远端模型读取失败不能按不存在处理；范围外影响未确认时可排除该模型及其依赖的更新。
