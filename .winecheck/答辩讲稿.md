## 正面开场（前 30 秒，先念这一段；再念下面的固定开场口径）

> **这一节是给评委的开场，不是降级声明**：下面「固定开场口径」那一段是诚实口径（模拟器证据、真机 0 台），

**① 用户痛点一句**：后端改完一个接口，Apifox 里的文档常常忘了跟着改——前端照着旧文档对接，联调时才发现字段对不上，
回头再核对一遍谁改了什么。这个工具替后端工程师把这一步做完：从 C# 源码找出与 Apifox 文档的差异，逐条列出来给你确认，
**只写你批准的那部分**。

**② 三个写入时刻一句**：与「批量导入 OpenAPI」的差别不在功能多少，在**写入的三个时刻**——**写之前**任何一次写入都有可核对的预览

**写之后**已完成的部分如实记下来，写完立即回读核对。

**③ 演示三步**（屏名与 `docs/NOTES.md`「降级答辩脚本」逐屏表同一份，念的时候照屏名点）：
1. **项目设置**——把仓库、API 项目、Apifox 项目与分支绑成一份可复用配置，并当场核对 CLI 版本、登录状态、项目可读性。
2. **检查任务 → 注释缺口 → 注释候选审阅**——扫出缺注释的位置，每条候选都带代码证据，逐条接受或搁置；接受的那部分才进回写。
3. **Apifox 差异检查 → 差异确认 → 同步预览 → 确认同步**——先只读比对出差异，高风险变化逐项确认，再冻结一份可核对的同步计划，
   确认之后逐项写入并立即回读核对。

**这一节不判什么**：不判真机观感（那是下面「固定开场口径」与 G-D5 的事），也不替代逐屏那一节的读数——
它只回答评委的第一个问题：「这个工具替谁省了什么事」。

## 当天四步（`defense-day.sh` 串的顺序，每一步：做什么 / 量到什么 / 缺什么）

### ① 到期日核对（`due-date.sh`）
- **做什么**：判今天是不是 2026-11-20；「已过」是退出码 1，于是第 ① 步就把「到期日之后还再烧三档」这条路挡住。
- **量到什么**：到期日由它自己现读 `docs/NOTES.md` 的 G-D5 那一格，脚本里一个日期字面量都不出现（`defense-day.sh` 与这页都不抄第二份）。
- **缺什么**：不判内容对不对、不判真机跑没跑，只决定「今天走哪一支」。

### ② 临场预检四条（`preflight.sh`）
- **做什么**：核 pwsh 在不在位、源码指纹是否与产物一致、三档是否跑过、九个真机归档目录是否到位。
- **量到什么**：四条各点一条自己的名；第 ④ 条「九个目录都在位」不等于「有东西」——现读仍是 `有东西的目录 0 / 9 个`、退出码 1。
- **缺什么**：带着预检没过跑第 ③ 步，念出来的数属于上一版源码或另一台机器；预检不过就停在这一条，不往下念「wine 量到」。

### ③ 三档冒烟与逐屏对账（`demo.sh`）
- **做什么**：按 `LogPixels` 96 / 120 / 192 各跑一次冒烟，把逐屏表每一行引用的冒烟段拿到该档报告里数「这一段在这一档通过几条、失败几条」，逐档出讲稿。
- **量到什么**：当前源码三档各 **450 通过 / 0 失败 ×3**（数字以 `.winecheck/reading.txt` 的 `tier=` 三行为准，这一句由门与它逐字对账）、逐屏对账 0 处对不上、量在 1600×1000 的 Xvfb 屏上。
- **缺什么**：**慢一档上下文**——那一跑里进程 DPI 跟着档位走、控件自报 DPI 慢一档（逐档 `96 / 96`、`96 / 120`、`120 / 192`），字体放大而行高不放大，所以「三档全绿」不能读成「行高预算在 125% / 200% 也过」。

### ④ 念序摘要与结尾固定一句
- **做什么**：从 `narration-<档位>.txt` 现读屏序（每屏：屏 / 讲什么 / 通过几条失败几条），再从 `demo.sh` 现读结尾那一句口径。
- **量到什么**：念序三档各 **27 屏**（屏数 = 逐屏表行数，与本页逐屏那一节同一份）。
- **缺什么**：结尾那一句只有一份出处（`demo.sh` 录制口径第 4 条），这页与 `defense-day.sh` 都从它现读、不各写一套。

### 被问到「按下『停止』那颗，屏上那句『正在停止…』呢？」——照这一段念

> 这一格是**模拟器量不到的那一段**，主动说明，别等被问到才翻不出读数。

- **判定 / 门 / 三屏接线都在**：那一句由 `Desktop/Native/JobOutcome.cs` 的 `StoppingText(kind, requested)` 一处给出（点过那颗「停止」且作业还在跑，才答「正在停止{种类}…当前步骤结束后停下。」；没点过答 `null`、各屏沿用自己那句进行中说明）；任务页、同步预览、连接与写入探测**三块屏各接一次并当场重画**；`StopRequestTests` 五条钉住——那一句全仓只写一次、三屏接线形状逐字相同、请求按**作业** Id 记、没收到作业不空说、那三颗钮的字面就是回应那句里用的那一个词。这些都是 Linux 上真执行的门，不是散文。
- **wine 里这一段一次没量到**：`RunJobOutcomeStatus` 三段量的是作业**结束之后**状态行说哪一句（成功 / 失败原因 / 已取消），那三段的读数在 96 / 120 / 192 三档各跑过；而**「请求已收下、作业还在跑」这一段量不到**。这里要说得比上一版准：第三百九十一轮试过一条不用造慢作业的量法——点『开始扫描』与点『停止』两次 `PerformClick` 之间一次消息都不泵，按「作业登记同步写下、摘登记只在线程池那一头」把那一击塞进那一段里。三档各跑一次，**每一档都红那两发**，于是这一条被自己那一跑证伪：`StartScan` 在起作业之后**自己就调一次 `RefreshDetail`**，那一次重画比这一页最快的一支作业跑得完还慢，等那一击落下去，作业已经到终态、只是还没摘登记；那一帧上那颗钮**来得及出现，但它是点不动的**（`Enabled` 跟着作业状态走——无物可停时本来就不该点得动，产品在这里没有错）。（那颗钮本身倒是在 `RunBannerFocus` 四段里三档各被走到、认得到，认不到即红。）
- **所以现场怎么念**：接线与门都在 ≠ 「模拟器量过那一句」；如实说「这一段要真机才看得到」，不要把「判定在」念成「读数在」。
- **要到真机才看得到什么**：真机上同步计划 / 分支检查 / 写入探测按项目大小是几秒到几十秒，那一句会真的停在屏上；且那一句是**换掉进度行那句「正在…40%」、字色仍是正文色**（与那句进行中说明同色），所以真机要看的不是颜色变没变，而是那一击之后**那句换没换过来、停留得够不够久、在实际字体与缩放下看不看得出点击收到了**——这一处不在「G-D5 真机复核清单」第 2 条（那条是行高预算），而在那一屏**主链路走一遍**时看；README「已知限制」里「正在停止…那一句没有 wine 读数」那条已把它指回 G-D5。
- **不为读数改产品取消语义**：造一个慢到能被点、能被取消的作业不是这一片的大小，也不该为凑一个读数去动作业的取消语义（`JobRunner.Cancel` 的协作式停止是产品定好的行为）；简报那条纪律照做。
