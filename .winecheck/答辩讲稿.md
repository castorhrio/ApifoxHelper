## 正面开场（前 30 秒，先念这一段；再念下面的固定开场口径）

### 被问到「按下『停止』那颗，屏上那句『正在停止…』呢？」——照这一段念

> 这一格是**模拟器量不到的那一段**，主动说明，别等被问到才翻不出读数。

- **判定 / 门 / 三屏接线都在**：那一句由 `Desktop/Native/JobOutcome.cs` 的 `StoppingText(kind, requested)` 一处给出（点过那颗「停止」且作业还在跑，才答「正在停止{种类}…当前步骤结束后停下。」；没点过答 `null`、各屏沿用自己那句进行中说明）；任务页、同步预览、连接与写入探测**三块屏各接一次并当场重画**；`StopRequestTests` 五条钉住——那一句全仓只写一次、三屏接线形状逐字相同、请求按**作业** Id 记、没收到作业不空说、那三颗钮的字面就是回应那句里用的那一个词。这些都是 Linux 上真执行的门，不是散文。
- **wine 里这一段一次没量到**：`RunJobOutcomeStatus` 三段量的是作业**结束之后**状态行说哪一句（成功 / 失败原因 / 已取消），那三段的读数在 96 / 120 / 192 三档各跑过；而**「请求已收下、作业还在跑」这一段量不到**。这里要说得比上一版准：第三百九十一轮试过一条不用造慢作业的量法——点『开始扫描』与点『停止』两次 `PerformClick` 之间一次消息都不泵，按「作业登记同步写下、摘登记只在线程池那一头」把那一击塞进那一段里。三档各跑一次，**每一档都红那两发**，于是这一条被自己那一跑证伪：`StartScan` 在起作业之后**自己就调一次 `RefreshDetail`**，那一次重画比这一页最快的一支作业跑得完还慢，等那一击落下去，作业已经到终态、只是还没摘登记；那一帧上那颗钮**来得及出现，但它是点不动的**（`Enabled` 跟着作业状态走——无物可停时本来就不该点得动，产品在这里没有错）。（那颗钮本身倒是在 `RunBannerFocus` 四段里三档各被走到、认得到，认不到即红。）
- **所以现场怎么念**：接线与门都在 ≠ 「模拟器量过那一句」；如实说「这一段要真机才看得到」，不要把「判定在」念成「读数在」。
- **要到真机才看得到什么**：真机上同步计划 / 分支检查 / 写入探测按项目大小是几秒到几十秒，那一句会真的停在屏上；且那一句是**换掉进度行那句「正在…40%」、字色仍是正文色**（与那句进行中说明同色），所以真机要看的不是颜色变没变，而是那一击之后**那句换没换过来、停留得够不够久、在实际字体与缩放下看不看得出点击收到了**——这一处不在「G-D5 真机复核清单」第 2 条（那条是行高预算），而在那一屏**主链路走一遍**时看；README「已知限制」里「正在停止…那一句没有 wine 读数」那条已把它指回 G-D5。
- **不为读数改产品取消语义**：造一个慢到能被点、能被取消的作业不是这一片的大小，也不该为凑一个读数去动作业的取消语义（`JobRunner.Cancel` 的协作式停止是产品定好的行为）；简报那条纪律照做。
