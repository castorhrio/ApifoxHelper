# wine 试跑脚本（开发期辅助，不属于产品运行路径）

本目录是开发期在 Linux 上用 wine 跑 Windows 桌面界面的辅助脚本：用来在没有 Windows 真机的环境里
把原生界面真的启动起来、点进去、截图看文字。**它们不参与构建、不被产品代码引用、不是用户路径**；
产品在 Windows 上的正常使用与这些脚本无关。

## 依赖

| 依赖 | 用途 | 实测版本 |
| --- | --- | --- |
| wine | 运行 Windows 版可执行文件 | wine-10.0（Ubuntu 打包版） |
| Xvfb | 无显示环境下的虚拟 X 服务器（脚本默认 `DISPLAY=:99`） | 随发行版 |
| xdotool | 找窗口、激活窗口、按坐标点击、真实键入 | 随发行版 |
| ImageMagick（`import` / `identify` / `convert`） | 截图与裁剪 | 随发行版 |
| tesseract（可选，中文需 `chi_sim` 语言包） | 把截图 OCR 成文字，核对界面上到底写了什么 | 随发行版 |

## 前置：先发布 Windows 版

```bash
dotnet publish ApifoxHelper.csproj -c Release -r win-x64 --self-contained -o /tmp/ah-pub
```

冒烟器（构造全部原生对话框并跑交互段）另有一份发布：

```bash
dotnet publish ApifoxHelper.Smoke/ApifoxHelper.Smoke.csproj -c Release -r win-x64 --self-contained -o /tmp/ah-smoke-pub
export WINEPREFIX=$HOME/.wine-ah
xvfb-run -a wine /tmp/ah-smoke-pub/ApifoxHelper.Smoke.exe --report=/tmp/ah-smoke-report.txt
```

**前缀必须是 `~/.wine-ah`（第一百六十六轮实测）**：不带 `WINEPREFIX` 走默认的 `~/.wine` 时，每一扇窗口都构造不出来——报告是 20 通过 / 115 失败，失败行全是 `Win32Exception：Error creating window handle`，三档缩放一样。那是那份前缀没有可用的桌面环境，不是产品的构造缺陷；照上面这一行设好前缀再判。

## 脚本

表里的每一行都必须对应磁盘上真实存在的一个 `.sh`，反过来也是——`WineCheckScriptsTests` 钉住这两侧对齐。

| 脚本 | 用途 |
| --- | --- |
| `run_app.sh` | 启动主窗口（`--data` 指向资料目录），先按进程名清掉上一次的实例，截图并 OCR 主窗口文字（`docs/NOTES.md` 两处证据行引用的是它） |
| `shot_dialog.sh` | 一条命令走完「启动 → 点空态「新建配置」→ 截图并 OCR 对话框」；参数 `$1` 等待秒数、`$2`/`$3` 点击坐标（坐标随 DPI 与字体变化，换机器后要重新量） |
| `fill.sh` | 在已打开的「新建配置」对话框里真实键入名称、仓库根目录与 API 项目路径，截图并 OCR |
| `demo.sh` | **降级答辩的一键复跑演示**：按 wine 三档缩放各跑一次冒烟，并把 `docs/NOTES.md`「降级答辩脚本」逐屏表的每一行与那一档的报告对上一次，逐档产出讲稿（用法见下一节） |
| `prepare-real-machine.sh` | **真机到手前的第 0 条四项准备，一条命令跑完**：① 复跑三档冒烟（调 `demo.sh`）→ ② 复跑 `dotnet build` 与 `dotnet test` → ③ 建好 `docs/evidence/real-machine/` 的九个归档子目录 → ④ 把 `docs/NOTES.md` 的七条动作单打印出来。任一步不过即非零退出并打出是哪一步（用法见下一节） |
| `collect-real-machine.sh` | **真机证据归档核对**：从 `docs/evidence/real-machine/README.md` 的产出物清单读目录名与应放文件名，逐个归档目录判「除隐藏占位（`.gitkeep` 这类）之外有没有东西」，还空着的逐条点名「哪一条动作还没归档、该往里放哪些文件」。退出码 `0` = 九个目录都不空、`1` = 还有目录空着（已点名）、`2` = 核对本身跑不动（清单读不到 / 解析不出七条动作 / 清单与磁盘的目录名对不上）。**不判内容对不对**（截图有没有裁切、读数三个数落得对不对要人看），也不替人打勾 |
| `preflight.sh` | **答辩当天的临场预检，一条命令核四件事**：① `pwsh` 找得到（`~/.dotnet/tools/pwsh` 或 PATH）；② 当前源码指纹 == 读数记录里的 `source=`；③ 三档演示跑过且通过（读数记录每档 `failed=0` 且 `exit=0`、冒烟器旁边有源码指纹）；④ 九个归档目录在位（调 `collect-real-machine.sh`，退出码 `2` 才算不在位）。任一条不过即非零退出并**点名到哪一步**。**不判内容对不对**，也不判真机跑没跑——九个目录都还空着（真机 0 台）不算预检失败 |
| `due-date.sh` | **到期日当天唯一能照着走的核对**：从 `docs/NOTES.md` 的 G-D5 行**现读**到期日（不抄第二份——脚本里一个日期字面量都没有），与系统日期比，三个分支各给一句当天能照着走的话：未到 → 「距到期还有 N 天，按现有路径继续」退出 `0`；当天 → 降级答辩三步（`PUBLISH=1 bash .winecheck/demo.sh` / 念 `narration-<档位>.txt` / 如实标 G-D5 未达成）退出 `0`；已过 → 「到期日已过，G-D5 应改判『已过期』」退出 `1`（「已过期」「降级」两个词与兄弟门 `Gd5DueDate_IsNotStaleOrFuture` ③ 逐字对齐）。退出码 `2` = 核对本身跑不动（NOTES 读不到 / G-D5 行找不到 / 行里没有日期 / `TODAY` 不是日期）。**不判真机跑没跑、不替人打勾、不改 G-D5 那一格** |

## 演示与录制口径（真机不可得时按此讲）

到期日 **2026-11-20** 仍拿不到 Windows 真机时，初审答辩按这一节讲。它是 `docs/NOTES.md`「降级答辩脚本」
一节的执行方式——**屏单只有一份，就是那张逐屏表**；脚本从表里读行，本 README 不再抄一份（抄的会漂）。

```bash
bash .winecheck/demo.sh                 # 三档各跑一次；产物在 /tmp/ah-demo
PUBLISH=1 bash .winecheck/demo.sh       # 冒烟器还没发布时，让脚本自己 dotnet publish
TIERS=96 bash .winecheck/demo.sh        # 只跑 100% 档（答辩前自查用，一集约 17 秒）
bash .winecheck/prepare-real-machine.sh # 真机到手前的第 0 条四项准备：①②③ 跑完 + ④ 打印七条动作单
bash .winecheck/collect-real-machine.sh # 真机证据归档核对：九个目录各自有没有东西、还空的该放什么（真机当天每跑完一条动作跑一次）
```

| 产物 | 内容 |
| --- | --- |
| `/tmp/ah-demo/report-<档位>.txt` | 该档冒烟报告原文，逐行 PASS/FAIL（缺省三档为 96 / 120 / 192） |
| `/tmp/ah-demo/narration-<档位>.txt` | 该档讲稿：每屏一段——屏名、讲什么、引用的段在该档通过几条失败几条、结论口径 |
| `/tmp/ah-demo/console-<档位>.log` | 该档 wine 控制台输出（报告没落盘时看这里） |

**录制与讲述顺序**：

1. 三档各录一段，录屏起点是脚本打出的「档位 LogPixels=…」那一行；屏幕固定 1600×1000（Xvfb）。
2. 按 `narration-<档位>.txt` 的行序讲（第 1 屏到最后一屏），每屏念「这一屏讲什么 / 这一段通过几条」。
   念的是报告里的数字，不是这里抄的一句话。
3. 结论口径写「源码 + 编译证据」的那几屏（生成文档核对 / Apifox 差异检查 / 同步预览与执行）
   **不演示界面**，只说「代码与用例在，真实端到端未跑」，不拿别的屏冒充。
4. 结尾固定一句：**以上均为 Linux 容器内 wine 10.0 + Xvfb 模拟器证据，不是 Windows 真机结果；
   真机 0 台，G-D5 未达成（环境供给缺口），到期日 2026-11-20。**

脚本的失败方式（都不是静默的）：报告没落盘、逐屏表某一行不是 5 列、表里引用的段在报告里找不到、
**产物的源码指纹与当前源码对不上（或指纹根本没有）**、或任何一屏的引用段有失败行——都非零退出，并打出是哪一屏哪一段。答辩前先看这一行，别带着失败念「wine 量到」。

**念出来的数必须出自当前源码**（第一百六十九轮在这上面连踩两次，两次都值得留字）：
`PUBLISH=1` 原先的条件是 `[ ! -f "$SMOKE_EXE" ]`，产物已存在就跳过发布，第二遍起跑用的是一小时前的产物——
三档「135 通过 / 0 失败」每一条都成立，念出来的却不是当前代码。这种数最难发现：它不报错、不失败。

现在的判据是**源码内容指纹**，不是文件时间：

| 项 | 内容 |
| --- | --- |
| 指纹怎么算 | 仓里所有 `.cs`（**排除** `ApifoxHelper.Tests/` 与 `bin`/`obj`）按路径排序后逐个 `sha1sum`，再对那份清单取一次 `sha1sum` |
| 记在哪里 | `$(dirname "$SMOKE_EXE")/smoke-source.sha`，即产物旁边 |
| `PUBLISH=1` 时 | `dotnet build -t:Rebuild` → `dotnet publish` → 重写指纹，然后才跑三档（这一支总是发自当前源码，无需再比） |
| 没设 `PUBLISH` 时 | 产物不在、指纹不在、或指纹与当前源码算出来的不一致——三种都非零退出，并把两边指纹打出来 |

两个坑各自为什么是那样：

- **mtime 那一条路走不通**（第一版就是它）：发布产物是 obj 的硬链接，增量构建不刷新它的时间戳，
  于是脚本打印的「重发再跑」做完了条件**依然成立**。教训不是「检查写错了」，而是
  **检查与它给的补救必须一起验**——只验「拦得住」而不验「按它说的做能不能通过」，交出去的是一个死门。
- **`ApifoxHelper.Tests/` 必须排除**：测试工程不编进这份产物，改了它不该要求重发冒烟器，
  否则每一轮改测试都会被自己的改动挡住。

跑完脚本把 `LogPixels` 改回 96（同一份前缀 `~/.wine-ah` 是共享的开发环境，别把下一个人留在 200% 档）。

## Windows 侧那支（`demo.ps1`）

`demo.sh` 是 bash，从未在 Windows（含 Git Bash / WSL / MSYS）跑过。`demo.ps1` 是同一份讲稿的那一支：
逐段同名、同读数、同一份逐屏表取法、同一份读数记录格式——由 `ApifoxHelper.Tests/WineCheckScriptsTests`
的两条门钉住（`DemoPs1_NamesTheSameSectionsAsDemoSh`、`BothDemoScripts_WriteTheSameReadingRecord`）。

```powershell
pwsh -File .winecheck/demo.ps1                    # 三档
pwsh -File .winecheck/demo.ps1 -Tiers 96          # 只跑 100% 档自查
pwsh -File .winecheck/demo.ps1 -Publish 1         # 让脚本自己重发冒烟器
```

旋钮与 `demo.sh` 同名（`REPO` / `NOTES` / `OUT` / `TIERS` / `PUBLISH` / `READING` / `WINE_BIN` /
`WINEPREFIX` / `DISPLAY`），也可以按 PowerShell 的写法用 `-Repo` / `-Notes` … 传参。

**这一支验到哪一层了（第二百零七轮 · 2026-11-12 实测，逐条可复跑）**：

1. **语法**：用 PowerShell 7.6.9（Linux 上的 `pwsh`，dotnet 全局工具）的
   `System.Management.Automation.Language.Parser::ParseFile` 解析过一遍——**0 处语法错误、1560 个 token**。
   这一条由 `DemoPs1_ParsesWithARealPowerShellParserWhenOneIsHere` 钉住：机器上有 PowerShell 就真解析，
   没有 PowerShell 的那台机器上判不到，此时**这一节就是唯一的登记**（所以别把它删掉）。
   另有一条不依赖任何外部工具的纯文本结构门 `DemoPs1_Structure_IsBalanced`（括号配平、引号与
   here-string 闭合、关键字成块），并带一条自测证明它抓得住注入的破坏。
2. **整支跑通**：第二百零七轮第一次真跑（Linux 容器内 pwsh 7.6.9 + wine 10.0 + Xvfb，三档跑完，退出码按
   实际读数给）。**第一次跑就被挡下**：它算出的源码指纹与 `demo.sh` 算出的不是同一个，于是判
   「冒烟器不是当前源码发出来的」并非零退出。根因在 `Get-SourceFingerprint` 用了 `Sort-Object` 默认的
   **区域语言序**（`ApiRoutes.cs` 排在 `ApifoxRoutes.cs` 之后），而 `demo.sh` 用 `LC_ALL=C sort` 的
   **字节序**——同一份源码两个指纹，两支脚本会互相把对方的产物判成过期。改成 `[Array]::Sort(..., Ordinal)`
   后两支对同一份源码算出同一个指纹（`f8a628b0…`）。
3. **100% 档读数同源**：`demo.ps1` 写出的 `narration-96.txt` 与 `demo.sh` 的那一份**逐字节相同**
   （只差输出目录），218 通过 / 0 失败。
4. **125% / 200% 两档的读数不同，如实记在这里**：`demo.ps1` 那一跑里冒烟器**控件自己报的 DPI 跟着档位走**
   （120 / 192），而 `demo.sh` 那一跑里它恒为 96（同一份产物、同一个前缀、同一个屏幕，两边各复跑两次
   都可复现）。**这两句在第二百零七轮写下时后面跟的是「机制未归因」；第二百一十一轮按简报 P0-2 在同一个
   容器里做了一次隔离实验，变量量到了：换档时是否重启 wine 前缀**——不是「bash 那一支」对「PowerShell 那一支」，
   见下面那张表（表里两个数是**实测**，不是推断）。

   同一份 `OUT`（两支缺省都是 `/tmp/ah-demo`）里先跑过 `demo.sh` 时，`narration-<档位>.txt` 里留着上一份讲稿，
   这一档的讲稿变成两份叠在一起：**实测 98 行 → 196 行**，现场会把每一屏念两遍，第 3 条那句「100% 档讲稿与
   `demo.sh` 逐字节相同」也当场不成立。**修法**：写讲稿前先把那一份截成空文件（`demo.sh` 一直有 `: >"$NARRATION"`，
   这一支补上同一件事）。**修后实测**：同一份 `OUT` 里再跑一次，`narration-96.txt` 回到 98 行，与 `demo.sh`
   那一份**逐字节相同**（只差输出目录那一行）。**门**：`WineCheckScriptsTests.DemoPs1_TruncatesTheNarrationBeforeWriting`
   判两支的截断都出现在第一次追加之前，并自带「删掉截断即红」的自测。
   **跑这一支时的一个坑（本轮踩到，如实记）**：`demo.ps1` 的 `READING` 缺省也指向仓里的 `.winecheck/reading.txt`，
   而它在本容器里跑出来是 230/1 与 229/2——**跑完仓里的读数记录就被覆盖成带失败的那一版**，
   `ReadingConsistencyTests` 会当场红（它判的是 `demo.sh` 那一跑的三档全绿）。本轮的做法是跑它时把
   `READING` 指到 `/tmp`，跑完再复跑一次 `demo.sh` 把记录写回 231 / 0 ×3；**脚本行为本轮未改**
   （读数记录记的是「这一跑量到了什么」，替它挑哪一跑该入库是另一件事，不在本轮范围）。


## 真机证据归档核对（`collect-real-machine.sh`）

「空目录 = 未达成」这句话此前只写在 `docs/evidence/real-machine/README.md` 与 `docs/NOTES.md` 里，
靠人自觉。这一支把它变成一条可跑的核对：**判的只有「有没有东西」**——一个归档目录里除了隐藏占位
（`.gitkeep` 这类以 `.` 开头的文件）之外有没有文件；有就打「已有 N 件」并把盘上的文件名念出来，
没有就打「还差东西」，再照着产出物清单打出这一条动作**该往里放哪些文件名**（清单里 `<档位>` 占位符
按目录名展开，`100/` 下就是 `100-主窗口.png`）。

**退出码念什么**：退出码 0 = 九个归档目录都不空了；退出码 1 = 还有目录空着（上面已逐个点名，G-D5 仍不能勾）；
退出码 2 = 这条核对本身跑不动（清单读不到、解析不出七条动作、**清单解析出的目录集合凑不满 9 个或同一个目录被点了两次**、
或清单与磁盘的目录名对不上）——那一天先修这一支，再谈证据。数动作的那一条只数「认出几条动作」，数不到目录：
把某一行的「归档目录」格改成不匹配的形状、而行数仍凑得够 7 时，正是目录集合那一条地板拦下来
（`WineCheckScriptsTests.CollectRealMachineScript_KeepsTheDirectorySetFloorAtNine`，第二百零九轮）。

**目录名与「该放什么」只有一份出处**：那张表在 `docs/evidence/real-machine/README.md`，脚本 awk 读它，
自己一个文件名都不写死——所以改清单不用改脚本，脚本里若抄了第二份清单，门会红
（`WineCheckScriptsTests.CollectRealMachineScript_NamesItsOwnFailureAndKeepsOneSourceOfTheFileList`）。
地板那两条也一样：脚本只写死**数量** 9，不写九个目录名；与那九个名字的逐个对齐由
`RealMachineEvidenceTests.ExpectedDirectories` 那份清单判。

**跑到了哪一层（第二百零八轮起 · 2026-11-12，Linux 容器实测，退出码与读数都是当场跑出来的）**：

「分支」那一格写的是**脚本里那一句失败消息的一段字面量**（不含被替换出来的那些值），由
`ApifoxHelper.Tests/MutationVerificationTests.cs` 逐条对着 `collect-real-machine.sh` 核：脚本里每一条
`exit 2` 都必须被这一列点到恰好一次，这一列也不许点到一条脚本里根本没有的话——**「实测可红」从这张表
的自述变成一条数得出来的对应关系**（第二百一十轮，简报 P1-1）。

| 场景 | 读数 | 分支（脚本里那一句的字面量） | 退出码 |
| --- | --- | --- | --- |
| 当前仓（九个目录只有 `.gitkeep`） | 有东西 0 / 9，九个目录逐个点名「还差东西」并打出该放的文件名 | 不是失败分支：退 1 说的是「活儿还没干完」 | `1` |
| 临时树，九个目录各塞一件真文件 | 有东西 9 / 9 | 不是失败分支：退 0 说的是「九个目录都不空了」 | `0` |
| 临时树，磁盘上多一个清单没点到的目录 | `② 未通过：磁盘上有清单没点到的目录：150/` | `磁盘上有清单没点到的目录` | `2` |
| 临时树，清单点到的目录被删掉 | `② 未通过：清单点到的目录在磁盘上不存在：125/` | `清单点到的目录在磁盘上不存在` | `2` |
| 临时树，README 某一行的一个目录格被删（7 行仍凑够，只剩 8 个目录） | `① 未通过：清单解析出 8 个归档目录（地板 9 个…）` | `个归档目录（地板 9 个` | `2` |
| 临时树，README 把动作 1 那一行复制一遍（同一目录点两次） | `① 未通过：清单把同一个归档目录点到两次：journey` | `清单把同一个归档目录点到两次` | `2` |
| 把清单文件删掉 | `① 未通过：找不到产出物清单：…` | `找不到产出物清单` | `2` |
| 临时树，README 删掉动作 4 那一行（只剩 6 条动作） | `① 未通过：清单解析出 6 条动作（应为 7 条）——表被改过，先核对表，再拿这一支出结论。` | `条动作（应为 7 条）` | `2` |
| 临时树，README 里那张表被整段删成散文 | `① 未通过：清单里一行都没解析出来（产出物那张表被改成散文了？没有表就无从核对）。` | `清单里一行都没解析出来` | `2` |
| 临时树，README 设成不可读（chmod 000） | `① 未通过：读 <那棵树>/README.md 时 awk 本身就失败了（不可读，或不是文本）。` | `时 awk 本身就失败了` | `2` |

**十条 = 八条 `exit 2` 分支 + 退 0 与退 1 各一行**，八条都在临时假树（或仓里当前那份清单）上真跑出过退出码：
前六条由 `RealMachineEvidenceTests.CollectScript_TreatsThePlaceholderAsEmptyAndNamesEveryDirectory`
的第 ⑤⑥⑦ 段跑，最后三条是同一段的第 ⑧⑨⑩ 段（第二百一十轮补，脚本本体一字未改——补的是「跑过并且留下读数」，
不是「加一条判据」）。「清单读不动」那一条要 Linux 的 `chmod` 真挡住读才造得出来，以 root 或带
`CAP_DAC_OVERRIDE` 跑的那台机器上造不出来，那一段就如实跳过这一支（不拿一份仍读得到的文件假装跑过），
而表与脚本的逐条对应由上面那条门不分路径判。

这些读数都由 `RealMachineEvidenceTests` 真跑这一支脚本判——
它不跑图形界面、不碰 wine，所以这一层在 Linux 上就是它的**全部行为**，不存在「Linux 绿了真机还不知道」。
第一条那一行（当前仓 0 / 9、退出码 1）就是本轮实测读数，也是 G-D5 至今未达成的直接证据。

**第一次跑就抓到它自己的一个缺陷**（记下来，因为它是这一族的老毛病）：念「已有 N 件」那一行原本用
`tr '\n' '、'` 把换行拼成顿号，实测吐出来的是 `0xE3` 一个碎片字节——`tr` 按字节处理，多字节分隔符
只保留最后一个字节，后面的 `sed 's/、$//'` 也就无从删起。改成 `awk 'NR > 1 { printf "、" }'` 逐行打分隔符。
仓里另外五支脚本没有同类 `tr` 用法（逐个查过）。

**它不判什么**：不判内容对不对（截图有没有裁切、读数那三个数落得对不对、字段名写没写都要人看）、
不打勾（勾由人按那份 README 的「什么算过」回写 `docs/NOTES.md`）、不判真机跑没跑（真机仍 0 台）。

**它自己的 Windows 面（如实挂账，与 `demo.ps1` 同一族）**：这一支是 bash，真机上要有 Git Bash / WSL
才跑得动；那台机器上若两者都没有，当天只能退回人工翻目录——**本轮没写 PowerShell 版**（简报把本轮范围
钉在这一件核心上），这一条随 G-D5 一起挂到真机当天。上面那五行读数全部是在 Linux 容器里跑的。

## 答辩当天预检（`preflight.sh`）

`preflight.sh` 把「临场才会暴露的失败点」收成一条命令，四条：① `pwsh` 找得到（`~/.dotnet/tools/pwsh` 或 PATH）；
② 当前源码指纹 == 读数记录里的 `source=`；③ 三档演示跑过且通过（读数记录每档 `failed=0` 且 `exit=0`、
冒烟器旁边有源码指纹）；④ 九个归档目录在位（调 `collect-real-machine.sh`，退出码 `2` 才算不在位）。
任一条不过即非零退出并**点名到哪一步**。它**不判内容对不对**，也**不判真机跑没跑**——九个目录都还空着
（真机 0 台）不算预检失败，那是 G-D5 的账。

**在真仓上真跑过一次（第二百二十四轮 · 2026-11-12，Linux 容器，读数当场跑出来的）**：

| 检查点 | 读数 |
| --- | --- |
| ① `pwsh` | 找到 `/home/ubuntu/.dotnet/tools/pwsh`（不在 PATH，按 `~/.dotnet/tools/pwsh` 找到——第二百零七轮那个教训的落点） |
| ② 源指纹 | 一致：`b7a63d2a9c12ffc3e954aba4e2479ad8badbb24e`（与 `.winecheck/reading.txt` 的 `source=` 逐字相同） |
| ③ 三档演示 | 3 档全部 0 失败、退出码 0；冒烟器源码指纹在位：`/tmp/ah-smoke-pub/smoke-source.sha` |
| ④ 九个归档目录 | 都在位，但都还空着（真机 0 台）——这一条判的是「在位」，空着不算预检失败 |
| 整支退出码 | `0`（四条都过，可以开讲） |

**这一行是读数不是判据**：它记的是「这一支在真仓上跑起来是什么样」，不是「它一定过」——换一台机器、
换一版源码、或读数记录被改过，②③ 就会红。预检本身的门（四个检查点的形状、失败分支各自点名、
在临时假树上把通过与不通过两个方向都跑活）在 `ApifoxHelper.Tests/PreflightScriptTests.cs`。
**它仍然不是真机证据**：上面这一跑全部在 Linux 容器里，G-D5 真机仍是 0 台、到期日 2026-11-20。

## 到期日核对（`due-date.sh`）

到期日这件事在仓里被写进了三处（`docs/NOTES.md` 的 G-D5 行、「到期日判定（细则）」子段、
「到期日当天执行单」那页），但**没有任何东西能在当天告诉人「现在该走降级还是该判过期」**——
两条既有门判的是「到期日不是过去的也不是未来的」与「那一段在位且日期一致」，**都判不到「今天是不是到期日」**。
`due-date.sh` 把那一格里的日期现读出来，与系统日期比，三个分支各给一句当天能照着走的话：

| 分支 | 打什么 | 退出码 |
| --- | --- | --- |
| 未到 | 「距到期还有 N 天，按现有路径继续」+ 指向「G-D5 真机复核清单（可勾选）」 | `0` |
| 当天 | 「今天是到期日」+ 降级答辩三步（`PUBLISH=1 bash .winecheck/demo.sh` / 念 `narration-<档位>.txt` / 如实标 G-D5 未达成）+ 指向 `collect-real-machine.sh` 的 0 / 9 触发条件 | `0` |
| 已过 | 「到期日已过，G-D5 应改判『已过期』」+ 回写落点（`docs/NOTES.md` G-D5 行，同一格必须同时留着「已过期」与「降级」） | `1` |
| 核对跑不动 | 点名是哪一种（NOTES 读不到 / G-D5 行找不到 / 行里没有日期 / `TODAY` 不是日期） | `2` |

**它不判什么**：不判真机跑没跑、不替人打勾、不改 G-D5 那一格（勾选框只由真机证据关闭），
也不判当天该选「按降级路径执行」还是「延后至某日」（那是答辩负责人的决定）。
**词表不在这里发明**：已过那一支打出来的「已过期」与「降级」，是兄弟门
`AcceptanceChecklistTests.Gd5DueDate_IsNotStaleOrFuture` ③ 在到期日过去之后读的那两个词——
`ApifoxHelper.Tests/DueDateScriptTests.cs` 从兄弟门源码里**现读**这两个词再对，兄弟门换词这一支就红。

**在真仓上真跑过（第二百二十五轮 · 2026-11-12，Linux 容器，读数当场跑出来的）**：
`TODAY=2026-11-12` → 「距到期还有 8 天」退出 `0`；`TODAY=2026-11-20` → 「今天是到期日」三步齐、退出 `0`；
`TODAY=2026-11-21` → 「到期日已过……已过 1 天」退出 `1`。**这一行是读数不是判据**：换一天、改期、
或 G-D5 那一行被改过，三个分支的输出就跟着变。

## 已知限制（不要拿它当 Windows 真机证据）

- wine 的字体度量与 GDI 绘制不是 Windows 实现：**观感、DPI 缩放、字体替换的结论不能替代真机复核**。
- 脚本里的点击坐标随 DPI 与字体变化，换机器或换字号后要重新量。
- 冒烟器能证明「对话框构造得起来、控件点得动、数据落得盘」，不能证明「界面好看」。
